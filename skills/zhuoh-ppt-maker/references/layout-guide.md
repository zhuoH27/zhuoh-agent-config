# 演示文稿与文献汇报·参考资料（排版细则与专项结构）

> 本文件是 `SKILL.md` 的拆层附件：主文件保留受众原则骨架、通用硬底线与学术答辩预设；此处存放七项表达原则细则、讲者建议与文献汇报专项规范全文。

## 一、内容表达原则细则
### 1. 讲好故事（篇章层）
**One deck, one story.** 整份演示围绕一条主线推进，而非平行罗列。
- **叙事链**（由科技论文 7W 改编）：① 背景与问题（从已知切入）→ ② 意义 → ③ 紧迫性 → ④ 难点 → ⑤ 方案与依据（交代为什么行得通）→ ⑥ 证据与结果 → ⑦ 结论与贡献 → ⑧ 行动。
- 决策型/阅读型前两页给压缩摘要；纯演讲型可保留适度悬念，但须让观众随时知道“讲到哪里”。

### 2. 一页一事与结构（篇章 + 页面层）
- **标准骨架**：封面 → 摘要 → 目录（≤10 页可省）→ 背景 → 问题 → 方案 → 论证与结果 → 结论 → 行动。
- 章节间设过渡页；每页只传达一个核心观点，**标题直接陈述本页结论**（不用“关于 XX 的介绍”类空泛名词；功能页除外）。

### 3. 由熟入生（页面 + 句子层）
- 从已知背景逐步引向新知，陌生概念先铺垫；口头衔接先回顾上页结论再引出新页；页内要点句“旧在前、新在句尾”。
- 受众水平差异大时，背景解释下沉备注、附录或备份页。

### 4. 恰当位置与视觉动线（页面层）
- 本页结论放标题，摘要在开头，行动在结尾，来源注释放页脚，图例紧靠图形；横排语言左上角与标题区是第一落点，**一页只设一个最强焦点**。

### 5. 长短句式与文字精简（页面 + 句子层）
**Slides are for scanning, not reading.** 每条要点 1 个话题（最多 2 个），动词紧靠主语、主动语态。
- **演讲型**：屏幕放关键词与短语（参考每页 6–7 行、每行 8–15 字），讲稿靠口头。
- **阅读型**：可用完整句，分层缩进、加粗关键词保持可扫读，细节进附录。

### 6. 可信度递减（篇章 + 页面层）
- 先摆权威数据与共识，再放推论与估计；多余弱证据进附录；结尾回扣核心结论或最强证据（不新增证据）。
- 受众已认同则直接给结论与行动；持怀疑态度则从共同前提出发。

### 7. 符合认知（页面 + 页内元素层）
- 因果型图表**自变量居左/横轴、因变量居右/纵轴**；看趋势/分布用图，查精确对照用表，2–3 个数字直接大字写出。
- 遵循设计四原则（对比、对齐、重复、亲密）；每页主图 1 个（最多 2–3 个且主次分明）。

## 二、讲者配套建议
- 不照念屏幕；先结论后依据；参考每页 1–2 分钟并留问答时间，准备备份页应对追问，排练修正卡壳与超时页。

## 三、文献汇报专项规范（基于论文/PDF 做组会汇报、论文解读或分享时触发）
> 引用与文字表达遵循 `zhuoh-paper-writing`（当前环境可读取其 `SKILL.md` 时直接参考；转录原文表格保持原文排布）。

### 1. 前置与默认场景
- **课题方向**：对话或材料中已有课题方向则直接紧扣（1.3 选择理由、4.3 启发）；未说明时，若用户要求直接产出或信息已足够，先按论文领域通用视角产出并在开头注明课题假设（不强行拦截打断），仅在高度依赖个人课题定制时用 1 句话询问。
- **默认场景（未指定时）**：混合场听众（领域专家挑方法 + 外行/决策者看价值与结论），30 分钟正式讲 + 提问。目标：① 外行听懂「痛点 → 做了什么 → 意味着什么」；② 专家确认研究扎实；③ 全场认可实际价值。

### 2. 交付形式与网页视觉
- **网页形态（HTML/SVG，默认首选）**：发挥网页长页滚动、分屏、步骤揭示、原文图叠加中文批注与局部放大优势；多图少字，术语用批注框解释。
  - **视觉自由度与底线**：正文等效 ≥18pt（24px）、最小可编辑文字 ≥14pt（19px），保持高对比度与克制学术配色（默认可用深灰/纯黑正文 + 学术主题色 + 红/绿功能框，或按用户要求采用纯黑白红预设）；默认单文件离线 HTML（CSS/SVG 内联，图多时配同级 `assets/`），不依赖外网资源，豁免 600 行上限。
- **PPTX 形态**：用户上传参考 PPT 要求复刻或明确要求 `.pptx` 时产出（未给参考 PPT 按 `SKILL.md` 学术答辩默认预设制作）。两形态共用同一套结论与数字。

### 3. 文献汇报结构（封面 → 目录 → 01 背景 → 02 方法 → 03 结果 → 04 讨论 → 致谢）
- **01 背景与摘要（≤ 全篇 1/4）**：
  - 1.1 期刊与作者：期刊/作者/单位取自原文；分区、影响因子、代表作仅取自用户提供或本次检索并标年份/来源，否则标 `[待补充]`。
  - 1.2 摘要拆解：分 3 节讲清背景痛点 / 方法一句话+流程图 / 结果关键数字 +「做了什么—数字—意义」三栏表。
  - 1.3 选择理由：本文目标 vs 我方课题目标对照表，为 4.3 埋伏笔。
  - 1.4 研究背景：前人工作对比表（时间/团队/做法/不足），条目仅取自原文或检索，缺失标 `[待补充]`，归纳不足标 `[推理]`，为 4.3 埋伏笔。
- **02 方法详解（全篇重心）**：2.1 整体框架图先行 → 2.2 提炼核心设计思想（传统 vs 本文对比）→ 2.3 起每步一节，采用三段式——**现存问题（红框）→ 解决方案（绿框）→ 原文图 + 中文标注**；复杂原理拆步讲。
- **03 结果分析**：每节一个结论，由浅入深排序（方法学验证 → 有效性 → 通用性 → 标志性/延伸应用），遵循「加粗一句话结论 + 原文图表 + 一句点评」。
- **04 讨论总结**：4.1 关键技术三栏表（方法 → 描述 → 优势）→ 4.2 局限与展望左右对照（区分作者自述与 `[推理]` 补充）→ 4.3 对课题的启发（4–5 条可迁移思路与落地方式，收回 1.3/1.4 伏笔）。
- **7W 对应**：W1–W4 → 01 背景；W5 → 02 方法；W6 → 03 结果；W7 → 04 讨论；缺失标 `[待补充]`。

### 4. 署名、复刻与备稿辅助
- **署名脱敏占位（默认）**：封面、页眉、致谢等署名处默认写「用户」「导师」，不自行猜测填写真实姓名、不留空（用户明确要求填写真实姓名时以用户为准）。
- **参考 PPT 风格复刻**：读取尺寸、母版、主题色、字体与骨架后替换为本次结论与数字；不带入原批注与备注；只读免备份，修改原文件先按铁律第 2 条备份。
- **备稿辅助**：默认在交付末尾附精炼的**主线讲法与时间分配**（30 分钟参考：背景 7 / 方法 12 / 结果 8 / 总结 3 min）；若用户要求准备试讲或完整备稿，再展开四件套（含每节保底一句、3 个专家可能质疑与回应、建议舍弃内容及理由）。
- **禁止项**：原文句子堆砌、无解释术语、跳过局限、背景超 1/4、方法缺三要素、网页硬仿 PPT 分页、用户要 `.pptx` 却只交网页、凭记忆填分区/影响因子/真实姓名。
