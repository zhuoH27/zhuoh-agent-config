# 演示文稿与文献汇报规范
> 核心思想：一切以受众为中心。好的演示不是作者自我展示，而是为受众铺一条从已知通往未知的路。适用学术、商务、科普类说明与说服型演示，以及基于论文/文献的组会与文献汇报；创意或营销类内容可按受众与场景取舍。
## 一、受众、底线与通用内容表达原则
### 0. 受众与目的先行与分层模型
动笔或做第一页前，先回答五个问题并压成一句话主线——**“对【谁】，我要让他【知道 / 相信 / 去做】【什么】”**：
1. **谁看？**（角色、立场：支持 / 中立 / 怀疑）
2. **已知什么？**（哪些术语、背景不用解释，哪些必须先定义）
3. **要他怎么样？**（知道、相信，还是去执行某项行动）
4. **什么场景？**（现场演讲型 / 自行阅读或会前预读型）
5. **有多少时间和注意力？**
- **分层不冲突**：篇章层“结论先行”；页面层“标题直接给结论”；句子层“旧信息在前、新信息在句尾”。三者作用层不同，互不冲突。
- **三项底线**：
  1. **诚信**：标注数据来源，区分事实与推断，不选择性展示；**不用截断坐标轴等手段制造夸大差异**（柱状图纵轴应从零开始；折线图等若不从零开始，须在图中明示）。
  2. **可及性**：保证文字与背景对比度；不只靠颜色传递信息（兼顾色觉障碍与黑白打印）；字号让后排或小屏清晰可读。
  3. **术语先定义**：对目标受众不熟悉的术语，首次出现前先定义或铺垫；**摘要与开篇不得使用未定义术语**。
### 1-7 项原则（骨架，细则见 references/layout-guide.md）
1. **讲好故事（篇章层）**：围绕一个中心命题组织全篇，开场与结论呼应。
2. **一页一事与结构（篇章+页面层）**：一页只承载一个信息点，同层信息同级呈现。
3. **由熟入生（页面+句子层）**：从听众已知引入未知，不先抛陌生术语。
4. **恰当位置与视觉动线（页面层）**：核心结论放注意力集中处，版面动线清晰。
5. **长短句式与文字精简（页面+句子层）**：短句要点化，长句拆分，控制每页文字量。
6. **可信度递减（篇章+页面层）**：证据由强到弱排列，形成印证链。
7. **符合认知（页面+页内元素层）**：因果型图自变量居左/横轴、因变量居右/纵轴。

## 二、视觉与排版硬性规范
1. **字体与字号底线**：
   - **字体搭配**：中文统一使用**微软雅黑（Microsoft YaHei）**，英文及数字统一使用 **Times New Roman**（全篇严格控制在 2 种字体以内）。
   - 用代码生成 PPT 时，必须同时显式设置 `a:latin`、`a:ea`、`a:cs`。`python-pptx` 的 `font.name` 只写入 `a:latin`，需操作 XML 补全。参考片段（已实测验证，仓库 `tests/test_pptx_font.py` 有对应测试）：
```python
from pptx.oxml.ns import qn
def set_run_fonts(run, zh="Microsoft YaHei", en="Times New Roman"):
    run.font.name = en  # 写入 a:latin
    rPr = run._r.get_or_add_rPr()
    latin = rPr.find(qn("a:latin"))
    ea = rPr.find(qn("a:ea"))
    if ea is None:
        ea = rPr.makeelement(qn("a:ea"), {})
        latin.addnext(ea)  # 保持 latin→ea→cs 的 schema 顺序
    ea.set("typeface", zh)
    cs = rPr.find(qn("a:cs"))
    if cs is None:
        cs = rPr.makeelement(qn("a:cs"), {})
        ea.addnext(cs)
    cs.set("typeface", en)
```
   - 表格单元格、母版与占位符的字体需单独检查，不能只处理普通文本框。
   - **字号层级**：正文优选 **18pt**（大厅投影宜更大）；全页任何元素最小字号**严禁低于 14pt**（14pt 仅限图注、表格单元格数据、页码等次要信息）。
   - **防拥挤原则**：内容放不下时，必须**精简文字提炼要点**或**拆分为多页**，**严禁缩小字号（低于 14pt）硬塞**。
2. **配色克制原则**：
   - 顶部标题栏可使用主题色。
   - 页面主体正文颜色**仅允许纯黑（`#000000`）或纯白（`#FFFFFF`）**（依据背景明暗反色，保证高对比度）；图注与页码等辅助元素允许使用中性深灰。
   - 仅允许对局部关键结论词句使用**红色**高亮强调，禁止大段文字飘红或引入花哨杂色。
   - 本配色规则**不适用于插图与图表内部**，不得为统一配色而改动图表原有配色；但须满足可及性底线（不只靠颜色区分数据）。
3. **段落缩进与行距**：
   - 仅当出现**长段落**（多句连贯成段文本）时，设置**首行缩进 2 字符**与 **1.5 倍行距**；短要点列表（Bullet Points）**不设首行缩进**，左对齐。
   - pptx 实现：段落属性 `marL="0"`，`indent = 字号pt × 2 × 12700`（EMU，18pt 即 457200），长段落需 `buNone`；行距用 `paragraph.line_spacing = 1.5`。
4. **关键插图视觉主体化**：
   - 核心原理图、实验装置图、数据对比图应尽量放大作为页面视觉主体，以占内容区（不含标题栏）面积 **≥ 50%** 为优先目标；确需缩小时须在汇报中说明原因。
   - 确保图内坐标轴标签、文字与细节清晰可辨，不得为堆砌文字把关键插图压缩成角落配角。
5. **渲染目检**：
   - 生成或修改后，若环境已安装 LibreOffice 等工具，转 PDF 或图片检查文字溢出与遮挡，渲染产物不得写入配置目录；未安装则在汇报中注明“未做渲染目检”。
   - 若系统缺少微软雅黑或 Times New Roman，渲染会替换字体，导致排版有偏差；渲染仅作溢出初筛，**字体合规以读取 XML 为准**。
## 三、讲者配套建议
- 不照念屏幕；先说结论再说依据；每页约 1-2 分钟并预留问答，准备备份页应对追问，排练记录卡壳超时处回头修改。细则见 `references/layout-guide.md`。

## 四、文献汇报专项规范（触发时须读 `references/layout-guide.md`）
- 仅当基于论文/文献/PDF 做组会汇报、论文解读或文献分享时触发；**完整专项规范已拆层至 `references/layout-guide.md`，触发本节时必须查阅该文件**。
- 参考 PPT 风格复刻时只读无需备份，修改则先按全局铁律第 2 条备份（可恢复）；- 核心不变项：引用与文字表达遵循 `zhuoh-paper-writing`（转录原文表格保持原排布）；未明确课题方向先问再产出；默认网页形态（离线单文件 HTML，豁免 600 行上限须注明），明确要 pptx 才出 pptx；结构为封面→目录→01 背景（≤1/4）→02 方法（重心，问题红框→方案绿框→原文图+中文标注三段式）→03 结果→04 讨论→致谢；署名脱敏写「用户」「导师」；备稿辅助四件套默认输出。

## 五、交付前自检清单
轻量任务只核对与本次改动直接相关的项；事实与安全底线不豁免。生成或修改 PPT/文献汇报后逐项核对，任一项不达标须先修正再交付。字号、字体须通过读取文件属性实测，不得凭印象判断。
- [ ] **一句话与标题串读**：能否用“对谁，让他知道/相信/去做某事”概括全篇？只读所有页面标题（功能页除外），能否复述全文脉络且每页标题均直接给出结论？
- [ ] **5 秒焦点与认知**：每页是否仅一个最强焦点（5 秒内最先看到最想被看到的内容）？自制因果表图是否自变量居左/横轴（文献汇报转录原文表保持原样）？
- [ ] **术语与新旧信息**：受众陌生术语是否在首次出现前已定义（摘要与开篇无未定义术语）？要点句是否旧在前、新在句尾且按场景控制了文字量？
- [ ] **诚信与可及性**：数据来源是否已标注，柱状图纵轴是否从零开始（未截断坐标轴制造夸大差异），去掉颜色后图表是否仍可读？
- [ ] **双字体与字号底线**：中文微软雅黑、英文数字 Times New Roman（pptx 需检查 `a:latin`/`a:ea`/`a:cs`、表格与母版；网页需 CSS 声明）；所有文字 ≥ 14pt（网页 ≥ 19px），且 14pt 仅用于次要信息？
- [ ] **配色纯净与缩进区分**：正文仅纯黑/纯白、辅助元素仅中性深灰、强调仅局部红（插图及文献汇报红绿功能框除外）；pptx 长段落 2 字符缩进 + 1.5 倍行距，短要点列表无缩进？
- [ ] **插图清晰与渲染目检**：核心插图以占内容区 ≥ 50% 为目标（未达则说明原因），图内文字清晰；pptx 是否已做渲染目检或注明未做？
- [ ] **文献汇报专项（仅文献汇报核对）**：课题方向与默认听众/时长已确认；署名使用「用户」「导师」；1.3/1.4 伏笔在 4.3 收回，背景 ≤ 1/4；方法含三要素；缺失信息标 `[待补充]`、推论标 `[推理]`；交付形式（默认离线网页并提示可复刻 PPT，或按要求交 .pptx）与引用规范（`zhuoh-paper-writing`）合规；离线 HTML 已注明豁免 600 行上限。
