# 演示文稿与文献汇报规范
> 核心思想：一切以受众为中心，为受众铺一条从已知通往未知的路。适用学术、商务、科普演示及基于论文/PDF 的组会文献汇报；创意或营销类按场景灵活取舍。

## 一、受众、底线与通用内容表达原则
### 0. 受众与目的先行
动笔前先压成一句话主线——**“对【谁】，我要让他【知道 / 相信 / 去做】【什么】”**（明确看客立场、已知背景、期望行动、现场演讲/自行阅读场景与时长）。
- **分层不冲突**：篇章层结论先行；页面层标题直接给结论；句子层旧信息在前、新信息在句尾。
- **三项硬底线**：
  1. **诚信**：标数据来源，区分事实与推断，**柱状图纵轴从零开始**（折线图不从零时须明示）。
  2. **可及性**：保证高对比度，不只靠颜色传递信息（兼顾色觉障碍与黑白打印），字号清晰可读。
  3. **术语先定义**：受众不熟悉的术语先定义或铺垫，摘要与开篇不得抛未定义术语。

### 1–7 项原则（骨架，细则见 `references/layout-guide.md`）
1. **讲好故事**：一份演示一个主线，开场与结论呼应。
2. **一页一事**：每页一个核心信息，标题直接陈述结论（功能页除外）。
3. **由熟入生**：从已知引入未知，陌生概念先铺垫。
4. **视觉动线**：核心结论放注意力集中处，一页只设一个最强焦点。
5. **精简句式**：短句要点化、动词靠主语，演讲型少字、阅读型分层可扫读。
6. **可信度递减**：强证据在前、弱证据在后，多余弱证据进附录。
7. **符合认知**：自制因果图/表自变量居左或横轴、因变量居右或纵轴（转录原文表保持原排布）。

## 二、视觉与排版规范（硬底线 vs 场景预设）
> **规则分层**：本节区分“所有场景必守的硬底线”与“无模板时的学术答辩默认预设”。用户或机构模板（含复刻参考 PPT）优先级最高。

### 1. 所有场景通用硬底线
- **字号与防拥挤**：PPTX 正文优选 **18pt**，任何可编辑文字**严禁低于 14pt**（14pt 仅限图注、表内次要数据、页码；插图内原始文字以清晰可辨为准）；网页正文等效 ≥18pt（24px）、最小可编辑文字 ≥14pt（19px）。放不下就精简或分页，**严禁缩小字号硬塞**。
- **关键插图主体化**：核心原理图、装置图、数据对比图优先作为视觉主体（目标占内容区面积 ≥50%），不得为堆字把关键图压成角落配角。
- **配色克制**：全篇主辅色控制在 2–3 种中性/克制色系内，保持正文与背景高对比度，不改动原文图表原有配色。
- **渲染目检**：生成或修改 `.pptx` 后，环境有 LibreOffice 等工具则转 PDF/图片检查溢出与遮挡（产物不入配置目录）；字体合规以读取 XML 为准。

### 2. 学术答辩 `.pptx` 默认预设（无模板且用户未另指定时使用）
> 商务、科普或现代 HTML 网页汇报在满足通用硬底线前提下，可采用更适合场景的克制现代配色与无衬线/衬线字族，不必僵化套用本预设。
- **双字体**：中文**微软雅黑（Microsoft YaHei）**，英文及数字 **Times New Roman**（全篇 ≤2 种字体）。用 `python-pptx` 生成时须同时设置 `a:latin`、`a:ea`、`a:cs`（`font.name` 只写入 `a:latin`，需补 `a:ea`/`a:cs` 并按 latin→ea→cs 的 schema 顺序插入；表格、母版与占位符一并检查）。参考实现见 `scripts/set_fonts.py`（`set_run_fonts()`，由 `tests/test_pptx_font.py` 实测覆盖）。
- **极简黑白红配色**：标题栏可用主题色；正文纯黑 `#000000` 或纯白 `#FFFFFF`，辅助元素中性深灰（如 `#666666`），仅局部关键结论用红（如 `#C00000`）高亮。
- **段落缩进**：仅长段落设首行缩进 2 字符（`marL="0"`，`indent = 字号pt × 2 × 12700`，`buNone`）+ 1.5 倍行距；短要点列表不缩进、左对齐。

## 三、文献汇报专项规范（触发时须读 `references/layout-guide.md`）
- 仅当基于论文/PDF 做组会汇报、论文解读或文献分享时触发，完整细则见 `references/layout-guide.md`。
- 参考 PPT 风格复刻只读免备份，修改原文件须按全局铁律 iron:recoverable 备份。
- **核心骨架**：引用与表达遵循 `zhuoh-paper-writing`（转录原文表保持原排布）；已知课题方向则紧扣，未知时先给通用视角或标注课题假设推进（不强行打断）；默认交付离线单文件 HTML（豁免 600 行上限，明确要 `.pptx` 再出 `.pptx`）；结构为封面 → 目录 → 01 背景（≤1/4）→ 02 方法（重心：问题红框 → 方案绿框 → 原文图+中文标注）→ 03 结果 → 04 讨论 → 致谢；署名默认写「用户」「导师」（用户明确指定真实姓名时以用户为准）；默认附精炼讲法要点（完整四件套按需展开）。

## 四、交付前核对（只查与本次改动直接相关项）
- **叙事与焦点**：标题串联能否复述主线？每页仅一个最强焦点？陌生术语已先定义？
- **诚信与可读性**：柱状图从零起、去色仍可读；所有可编辑文字 ≥14pt（网页 ≥19px），关键插图清晰放大；`.pptx` 已查 XML 字体与渲染目检（未安装渲染工具简短注明）。
- **文献汇报专项**：背景 ≤1/4、方法含三要素、伏笔首尾呼应、署名默认用「用户」「导师」（用户指定除外）、缺失标 `[待补充]`、推论标 `[推理]`。
