# 演示文稿与文献汇报规范
> 核心思想：一切以受众为中心。好的演示不是作者自我展示，而是为受众铺一条从已知通往未知的路。适用学术、商务、科普类说明与说服型演示，以及基于论文/文献的组会与文献汇报；创意或营销类内容可按受众与场景取舍。
## 一、受众、底线与通用内容表达原则
### 0. 受众与目的先行与分层模型
动笔或做第一页前，先回答五个问题并压成一句话主线——**“对【谁】，我要让他【知道 / 相信 / 去做】【什么】”**：
1. **谁看？**（角色、立场：支持 / 中立 / 怀疑）
2. **已知什么？**（哪些术语、背景不用解释，哪些必须先定义）
3. **要他怎么样？**（知道、相信，还是去执行某项行动）
4. **什么场景？**（现场演讲型 / 自行阅读或会前预读型）
5. **有多少时间和注意力？**
- **分层不冲突**：篇章层“结论先行”；页面层“标题直接给结论”；句子层“旧信息在前、新信息在句尾”。三者作用层不同，互不冲突。
- **三项底线**：
  1. **诚信**：标注数据来源，区分事实与推断，不选择性展示；**不用截断坐标轴等手段制造夸大差异**（柱状图纵轴应从零开始；折线图等若不从零开始，须在图中明示）。
  2. **可及性**：保证文字与背景对比度；不只靠颜色传递信息（兼顾色觉障碍与黑白打印）；字号让后排或小屏清晰可读。
  3. **术语先定义**：对目标受众不熟悉的术语，首次出现前先定义或铺垫；**摘要与开篇不得使用未定义术语**。
### 1. 讲好故事（篇章层）
**One deck, one story.（一份演示，一个故事）**
- 整份 PPT 围绕一条主线，只回答一个中心问题，页与页之间是逻辑推进而非平行罗列。
- **PPT 叙事链**（由科技论文 7W 改编）：① 背景与问题（从已知切入）→ ② 意义（为什么听）→ ③ 紧迫性（为什么现在）→ ④ 难点（为什么不容易）→ ⑤ 方案与依据（**必须交代为什么行得通**）→ ⑥ 证据与结果 → ⑦ 结论与贡献（回扣主线）→ ⑧ 行动（受众接下来做什么）。
- **摘要页**：决策型、阅读型 PPT 在前两页给出整条叙事链的压缩版（核心结论先行）；纯演讲型可保留适度悬念，但须让观众始终知道“现在讲到哪里”。
### 2. 一页一事与结构（篇章 + 页面层）
**Structure serves the audience, not the author.**
- **标准骨架**：封面 → 摘要 → 目录 → 背景 → 问题（含意义、紧迫性、难点）→ 方案 → 论证（含结果）→ 结论 → 行动。10 页或 10 分钟以内的短演示，目录页可省略。
- **连贯性**：章节间设过渡页，章内页序环环相扣；创新性体现在内容上，不体现在花哨版式、动画与转场上（学术与商务场景）。
- **一页一事，标题即结论**：每页只传达一个核心信息；页面标题直接陈述本页结论/观点（如不使用“关于 XX 的介绍”等空泛名词标题；目录页、过渡页等功能页除外）。
### 3. 由熟入生（页面 + 句子层）
- 页面顺序从观众已知背景讲起，逐步引向新知；对陌生概念必须先有铺垫页或定义。
- 口头衔接先用一句话回顾上一页结论（旧信息），再引出本页新内容；页内要点句遵循“旧在前、新在句尾”。
- 受众水平差异大时，将背景解释放入备注、附录或备份页，不打断主线。
### 4. 恰当位置与视觉动线（页面层）
- **期待位置**：本页结论放标题；摘要在开头，行动建议在结尾；数据来源与注释放页脚；图例与标签紧靠所标图形；页码与章节标识位置固定（有机构模板时以模板为准）；适当处做交叉引用（“如第 X 页所示”）。
- **视线落点**：横排从左到右阅读的语言，视线大致从左到右、从上到下，左上角与标题区是第一落点（从右向左语言镜像处理）；大图、人脸、高对比色块会抢夺视线，有意识把核心信息置于视觉焦点，**一页只设一个最强焦点**。
### 5. 长短句式与文字精简（页面 + 句子层）
**Slides are for scanning, not reading.**
- 每条要点 1 个话题（最多 2 个），短语化为主；必须用完整句时**动词紧靠主语**，优先主动语态与具体主语。
- **区分场景控制文字量**：
  - **演讲型（有人讲）**：屏幕放关键词与短语，讲稿靠口头表达；参考每页正文约 6–7 行、每行约 8–15 字短语。
  - **阅读型（自读/预读）**：可用完整句，但须分层缩进、加粗关键词保持可扫读，每页仍只传达一个核心信息；细节下沉附录与备注。
### 6. 可信度递减（篇章 + 页面层）
- **由强到弱**：先摆权威数据、公认事实、共识结论，再呈现推论、估计与猜想；强证据先获认同后，弱证据更易被接受，质疑也能聚焦到单页而非全盘否定。
- **证据广度与克制**：多角度非完全归纳形成相互印证的证据链；但证据不是越多越好，多余弱证据会拉低整体说服力，可移入附录备查。
- **结尾回扣**：结尾复述核心结论或最强证据（不新增证据）。
- **例外调整**：受众已认同结论时直接给结论与行动；持敌意或怀疑态度时先从共同前提出发；故事型演讲可先设悬念再兑现。
### 7. 符合认知（页面 + 页内元素层）
- **因果方向**：图表中**自变量（原因、条件）放左侧或横轴，因变量（结果）放右侧或纵轴**，符合“先因后果、自左向右”的认知习惯。
- **按任务选形式**：看趋势/比较/分布/占比 → 图；查精确数值/多维对照 → 表；仅 2–3 个关键数字 → 直接大字写出；解释因果/限定条件/逻辑 → 简短文字或结构图。
- **设计四基本法（CRAP）**：对比（突出重点）、对齐（秩序感）、重复（统一风格）、亲密（相关内容靠近）。
- **信息密度**：每页主要图表 1 个（最多 2–3 个且主次分明），以观众一眼能分清主次为限。
## 二、视觉与排版硬性规范
1. **字体与字号底线**：
   - **字体搭配**：中文统一使用**微软雅黑（Microsoft YaHei）**，英文及数字统一使用 **Times New Roman**（全篇严格控制在 2 种字体以内）。
   - 用代码生成 PPT 时，必须同时显式设置 `a:latin`、`a:ea`、`a:cs`。`python-pptx` 的 `font.name` 只写入 `a:latin`，需操作 XML 补全。参考片段（`[未经实际验证]`，使用前必须在目标环境实测，并读取生成文件的 XML 核对）：
```python
from pptx.oxml.ns import qn
def set_run_fonts(run, zh="Microsoft YaHei", en="Times New Roman"):
    run.font.name = en  # 写入 a:latin
    rPr = run._r.get_or_add_rPr()
    latin = rPr.find(qn("a:latin"))
    ea = rPr.find(qn("a:ea"))
    if ea is None:
        ea = rPr.makeelement(qn("a:ea"), {})
        latin.addnext(ea)  # 保持 latin→ea→cs 的 schema 顺序
    ea.set("typeface", zh)
    cs = rPr.find(qn("a:cs"))
    if cs is None:
        cs = rPr.makeelement(qn("a:cs"), {})
        ea.addnext(cs)
    cs.set("typeface", en)
```
   - 表格单元格、母版与占位符的字体需单独检查，不能只处理普通文本框。
   - **字号层级**：正文优选 **18pt**（大厅投影宜更大）；全页任何元素最小字号**严禁低于 14pt**（14pt 仅限图注、表格单元格数据、页码等次要信息）。
   - **防拥挤原则**：内容放不下时，必须**精简文字提炼要点**或**拆分为多页**，**严禁缩小字号（低于 14pt）硬塞**。
2. **配色克制原则**：
   - 顶部标题栏可使用主题色。
   - 页面主体正文颜色**仅允许纯黑（`#000000`）或纯白（`#FFFFFF`）**（依据背景明暗反色，保证高对比度）；图注与页码等辅助元素允许使用中性深灰。
   - 仅允许对局部关键结论词句使用**红色**高亮强调，禁止大段文字飘红或引入花哨杂色。
   - 本配色规则**不适用于插图与图表内部**，不得为统一配色而改动图表原有配色；但须满足可及性底线（不只靠颜色区分数据）。
3. **段落缩进与行距**：
   - 仅当出现**长段落**（多句连贯成段文本）时，设置**首行缩进 2 字符**与 **1.5 倍行距**；短要点列表（Bullet Points）**不设首行缩进**，左对齐。
   - pptx 实现：段落属性 `marL="0"`，`indent = 字号pt × 2 × 12700`（EMU，18pt 即 457200），长段落需 `buNone`；行距用 `paragraph.line_spacing = 1.5`。
4. **关键插图视觉主体化**：
   - 核心原理图、实验装置图、数据对比图应尽量放大作为页面视觉主体，以占内容区（不含标题栏）面积 **≥ 50%** 为优先目标；确需缩小时须在汇报中说明原因。
   - 确保图内坐标轴标签、文字与细节清晰可辨，不得为堆砌文字把关键插图压缩成角落配角。
5. **渲染目检**：
   - 生成或修改后，若环境已安装 LibreOffice 等工具，转 PDF 或图片检查文字溢出与遮挡，渲染产物不得写入配置目录；未安装则在汇报中注明“未做渲染目检”。
   - 若系统缺少微软雅黑或 Times New Roman，渲染会替换字体，导致排版有偏差；渲染仅作溢出初筛，**字体合规以读取 XML 为准**。
## 三、讲者配套建议
- 不照念屏幕；先说结论，再说依据。
- 参考每页分配约 1–2 分钟并预留问答时间，准备备份页（附录）应对可预见的追问；排练时记录卡壳、超时与易困惑处并回头修改页面。
## 四、文献汇报专项规范（仅当基于论文/文献/PDF 做组会汇报、论文解读或文献分享时触发）
> 文献汇报涉及的引用格式与反编造要求遵循 `paper-writing`（内含引用规范）；文字表达与图表排布亦遵循 `paper-writing`（但转录原文表格保持原文排布，不为“自变量居左”擅自调换）。若本任务未同时加载 `paper-writing`，先读取 `<skills 目录>/paper-writing/SKILL.md`。
### 1. 执行前置动作与默认场景
- **强制前置**：若当前对话上下文或已提供材料中尚未明确用户课题方向，开始设计前必须先询问并得到明确答复后方可产出大纲与页面；若用户已明确给出课题方向，直接沿用并在大纲开头确认，不重复打断。所有与课题关联的内容（1.3 选择理由、4.3 启发）必须紧扣该方向。
- **默认场景（用户未指定时）**：听众为混合场——领域专家（挑方法毛病）+ 外行决策者（关心价值和结论）；时长为 30 分钟正式讲 + 提问；默认值与课题方向在大纲开头合并为一行确认。目标优先级：① 外行听懂「为什么重要 → 具体做了什么 → 意味着什么」完整链条；② 专家从取舍与预判中确认研究扎实；③ 所有人认可实际价值。
### 2. 交付形式与默认流程
- **网页形态汇报（HTML/SVG，默认首选呈现形态）**：
  - 不受 PPT 16:9 画幅与分页约束，按内容逻辑自由组织版面（长页滚动叙事、左右分屏、时间轴、分步揭示、信息图等），主动发挥网页优势（机制分步动画、数据高亮、原文图叠加中文批注、局部放大）。
  - **多图少字**：优先放大原文插图与自制示意图，文字精炼为短句要点并保留具体数字，术语用批注框解释。
  - **网页视觉换算**：CSS `font-family` 同时声明微软雅黑与 Times New Roman；正文等效 ≥18pt（24px）、任何文字 ≥14pt（19px）；正文颜色仅黑/白，强调仅局部红（红/绿功能框例外）。
  - **离线可用**：默认单文件 HTML（CSS/SVG 内联）；插图较多时允许「主 HTML + 同级 `assets/` 本地图片目录」，不依赖外网资源。该离线文献汇报 HTML 豁免 `code-standards` 的 600 行上限（须在汇报中注明）。
- **演示文稿形态（.pptx）**：当用户上传参考 PPT 要求复刻，或明确要求 pptx 时产出（可另出逐页高清 PNG）。
- **默认流程**：用户未明确要求 pptx 时先只交付网页形态，并在汇报末尾提示：如需 PPT 版本，请提供参考 PPT，将按其风格复刻；明确要求 pptx 但未提供参考 PPT 的按第二节默认规范制作；两形态共用同一套结论与数字。
### 3. 文献汇报结构（封面 → 目录 → 01 背景 → 02 方法 → 03 结果 → 04 讨论 → 致谢）
- **01 背景与摘要（≤ 全篇 1/4）**：
  - 1.1 期刊与作者：期刊名、作者、单位取自原文；分区、影响因子、代表作仅来自用户提供或本次检索并标年份/来源，否则标 `[待补充]`。
  - 1.2 摘要拆解：分 3 页展示 abstract 原文，讲清背景痛点 / 方法一句话+流程图 / 结果关键数字 +「做了什么—数字—意义」三栏表。
  - 1.3 选择理由：本文目标 vs 我方课题目标对照表，为 4.3 埋伏笔，形成首尾闭环。
  - 1.4 研究背景：前人工作对比表（时间/团队/做法/不足），条目仅取自本文引言/引文或检索材料，缺失标 `[待补充]`，归纳性“不足”标 `[推理]`。
- **02 方法详解（全篇重心）**：2.1 整体框架图先行 → 2.2 提炼 1 个核心设计思想（「传统做法 vs 本文做法」对比）→ 2.3 起按流程每步一节，统一三段式模板——**现存问题（红框）→ 解决方案（绿框）→ 原文图 + 中文标注**；复杂原理单独拆节分步讲。
- **03 结果分析**：每节一个结论，由浅入深排序（参数优化/方法学验证 → 有效性 → 通用性 → 标志性应用 → 延伸应用），遵循「一句话结论（加粗）+ 原文图表 + 一句点评」，图下标图号与中文说明。
- **04 讨论总结**：4.1 关键技术三栏表（方法 → 描述 → 优势）→ 4.2 局限与展望左右对照（区分“作者自述”与“`[推理]` 补充”）→ 4.3 对课题的启发（4–5 条可迁移思路与具体落地方式）。
- **7W 对应**：W1–W4 → 01 背景；W5 → 02 方法；W6 → 03 结果；W7 → 04 讨论；答案取自原文与用户材料，缺失标 `[待补充]`。
### 4. 署名、功能色、参考 PPT 复刻与备稿辅助
- **署名脱敏占位（强制）**：封面、页眉、致谢等署名处一律写「用户」（汇报人）与「导师」（指导教师），不得填入或猜测真实姓名、不得留空，并在汇报中提醒用户最终对外提交前替换。
- **功能色例外**：方法三段式的「现存问题红框 / 解决方案绿框」框线与浅色底纹不受正文黑白配色限制；框内文字仍须纯黑/纯白。
- **参考 PPT 风格复刻**：先读取参考 PPT 的尺寸、母版、主题色、字体与页面骨架并复刻，再替换为本次汇报结论与数字；不带入参考文件批注、备注页与原内容；只读参考文件无需备份，修改则先按全局铁律第 2 条备份。
- **备稿辅助交付物（默认输出到对话或单独文档，用户可声明跳过）**：① 主线故事与时间分配（30 分钟参考：背景约 7 min / 方法约 12 min / 结果约 8 min / 总结约 3 min，其他时长按比例折算，标出专家深挖点）；② 每小节“只能讲一句”保底版；③ 最可能被专家质疑的 3 个点 + 回应策略（标 `[推理]`）；④ 建议舍弃内容及理由。
- **文献汇报禁止项**：用原文句子堆砌；无解释的术语；跳过 limitations；背景超 1/4；方法缺少「问题 → 方案 → 图示」三要素；网页模仿 PPT 分页或大段堆字；用户明确要 .pptx 却只交网页；凭记忆填分区/影响因子/作者信息/前人条目或写入真实姓名。
## 五、交付前自检清单
轻量任务只核对与本次改动直接相关的项；事实与安全底线不豁免。生成或修改 PPT/文献汇报后逐项核对，任一项不达标须先修正再交付。字号、字体须通过读取文件属性实测，不得凭印象判断。
- [ ] **一句话与标题串读**：能否用“对谁，让他知道/相信/去做某事”概括全篇？只读所有页面标题（功能页除外），能否复述全文脉络且每页标题均直接给出结论？
- [ ] **5 秒焦点与认知**：每页是否仅一个最强焦点（5 秒内最先看到最想被看到的内容）？自制因果表图是否自变量居左/横轴（文献汇报转录原文表保持原样）？
- [ ] **术语与新旧信息**：受众陌生术语是否在首次出现前已定义（摘要与开篇无未定义术语）？要点句是否旧在前、新在句尾且按场景控制了文字量？
- [ ] **诚信与可及性**：数据来源是否已标注，柱状图纵轴是否从零开始（未截断坐标轴制造夸大差异），去掉颜色后图表是否仍可读？
- [ ] **双字体与字号底线**：中文微软雅黑、英文数字 Times New Roman（pptx 需检查 `a:latin`/`a:ea`/`a:cs`、表格与母版；网页需 CSS 声明）；所有文字 ≥ 14pt（网页 ≥ 19px），且 14pt 仅用于次要信息？
- [ ] **配色纯净与缩进区分**：正文仅纯黑/纯白、辅助元素仅中性深灰、强调仅局部红（插图及文献汇报红绿功能框除外）；pptx 长段落 2 字符缩进 + 1.5 倍行距，短要点列表无缩进？
- [ ] **插图清晰与渲染目检**：核心插图以占内容区 ≥ 50% 为目标（未达则说明原因），图内文字清晰；pptx 是否已做渲染目检或注明未做？
- [ ] **文献汇报专项（仅文献汇报核对）**：课题方向与默认听众/时长已确认；署名使用「用户」「导师」；1.3/1.4 伏笔在 4.3 收回，背景 ≤ 1/4；方法含三要素；缺失信息标 `[待补充]`、推论标 `[推理]`；交付形式（默认离线网页并提示可复刻 PPT，或按要求交 .pptx）与引用规范（`paper-writing`）合规；离线 HTML 已注明豁免 600 行上限。
