# 代码与前端工程规范

## 一、核心规则

1. **新建与整文件重写上限（≤ 600 行）**：
   - 新建或整文件重写业务逻辑源码与 UI 组件文件时，单文件总行数**严格不超过 600 行**。
   - 预估代码量将超过 600 行时，必须在编码前先按功能职责拆分为多个独立模块。
   - **豁免范围**：声明式数据与配置文件（`.json`、`.yaml`、`.sql`）、`.md` 文档、测试 fixture、自动生成代码（不手改）、迁移文件、第三方 vendored 代码，以及用户明确要求“单文件离线交付”的完整 HTML 页面或按 `zhuoh-ppt-maker` 文献汇报模式产出的离线文献汇报 HTML 页面（含配套本地 `assets/` 图片资源）。豁免文件必须在汇报中注明。

2. **存量超长文件保护（最小必要改动）**：
   - 局部修改原本已超过 600 行的存量旧文件时，**仅允许做最小必要改动**。
   - 严禁未经用户明确指令对存量超长文件进行全量重写或顺手大规模重构。
   - 修改完成后在汇报中提示该文件已超 600 行并建议后续拆分；**同一会话内同一文件只提示一次**。轻量任务以一句话回报满足此提示，不触发完整汇报。

3. **前端样式约束**：
   - 先检查项目已有样式体系（`package.json`、配置文件、现有组件），**已有体系则沿用**（如 Ant Design、Element、CSS Modules、已有 Tailwind 配置等）。
   - 无既有体系且为新建独立页面时，默认使用 **Tailwind CSS**。
   - 若用户要求“可直接双击离线打开的单文件 HTML 页面”或按 `zhuoh-ppt-maker` 文献汇报模式产出文献汇报网页，允许使用内联 `<style>`，并在汇报中注明。

4. **界面提示克制（布局优先于说明）**：
   - 避免不必要的辅助标签、说明文字、占位提示与装饰性徽标，让布局结构、留白与视觉层级本身发挥解释作用。
   - 提示遵循**最少必要**原则：常规且可撤销的操作不加确认弹窗与辅助说明；仅在操作**有歧义**（含义不明、存在多种理解）或**不可逆**（删除、覆盖、对外发送等）时保留提示与二次确认。

5. **版本号与时间戳命名规则**：
   - **版本号沿用项目既有体系**（语义化版本如 `1.2.3`、日期代号、时间戳等）：适用于代码内版本标识（`__version__`、`VERSION` 常量、`package.json` 的 `version` 等）、提交说明中的版本标识与交付文件命名中的版本号；项目已有方案就延续，用户明确指定按用户指定，自动生成代码中由工具链维护的版本号不手改。新建项目无既定方案时：对外分发或发包的用语义化版本，其余默认用 14 位时间戳版本 `YYYYMMDDHHMMSS`（如 `20261124213311`）。豁免与偏离须在汇报中注明。
   - **时间戳仅用于产物与备份命名**：格式 `YYYYMMDD_HHMMSS`，精确到秒（如 `20260101_000000`）。备份命名严格按铁律第 2 条（`<原名>_YYYYMMDD_HHMMSS.<原扩展名>.bak`，重名加 `_2`、`_3`）；非备份产物同秒碰撞追加 `-NN` 序号（如 `20260101_000000-01`）；交接小节标题的 `## YYYY-MM-DD HH:MM:SS <来源>` 格式属铁律第 9 条，不受本条格式约束。
   - **生成方式**：时间戳必须用一次性命令实时获取，**严禁凭记忆估算填写**。Git Bash：`date +%Y%m%d_%H%M%S`；PowerShell：`Get-Date -Format "yyyyMMdd_HHmmss"`；Python：`datetime.now().strftime("%Y%m%d_%H%M%S")`（14 位版本号即去掉下划线）。时区默认使用**本地时间**。

## 二、交付前自检清单

轻量任务只核对与本次改动直接相关的项；铁律第 1、3 条不豁免。输出代码或结束任务前逐项核对，任一项不达标须先修正再交付。行数必须用一次性命令实测，不得估算（Git Bash：`wc -l <文件>`；PowerShell：`(Get-Content -LiteralPath <文件>).Count`；`wc -l` 数的是换行符，末行无换行会少计 1，行数处于边界值时须复核）。

- [ ] **行数核对**：本次新建或整文件重写的源码/组件文件，实测总行数是否均 ≤ 600 行？豁免文件是否已在汇报中说明？
- [ ] **存量保护**：若修改了原本 > 600 行的旧文件，是否严格控制为最小局部改动，且已在汇报中提示拆分（同一会话同一文件仅一次）？
- [ ] **样式合规**：是否已先检查并沿用项目既有样式体系？无既有体系的新建页面是否使用 Tailwind CSS？因离线单页 HTML 使用内联 CSS 的，是否已在汇报中注明？
- [ ] **提示克制**：界面是否已去除不必要的辅助标签与说明文字？确认类提示是否仅保留在有歧义或不可逆的操作上？
- [ ] **版本与命名核对**：版本号是否沿用项目既有体系（新建项目无既定方案时默认时间戳版本）？产物与备份命名的时间戳是否为 `YYYYMMDD_HHMMSS` 且由命令实时生成而非估算？备份重名是否按铁律第 2 条用 `_2`/`_3`？豁免场景是否已在汇报中注明？
