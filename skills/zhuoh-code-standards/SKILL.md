# 代码与前端工程规范
## 一、核心规则
1. **新建与整文件重写上限（≤ 600 行）**：
   - 新建或整文件重写业务逻辑源码与 UI 组件文件时，单文件总行数**严格不超过 600 行**。
   - 预估代码量将超过 600 行时，必须在编码前先按功能职责拆分为多个独立模块。
   - **豁免范围**：声明式数据与配置文件（`.json`、`.yaml`、`.sql`）、`.md` 文档、测试 fixture、自动生成代码（不手改）、迁移文件、第三方 vendored 代码，以及用户明确要求“单文件离线交付”的完整 HTML 页面或按 `zhuoh-ppt-maker` 文献汇报模式产出的离线文献汇报 HTML 页面（含配套本地 `assets/` 图片资源）。豁免文件必须在汇报中注明。
2. **存量超长文件保护（最小必要改动）**：
   - 局部修改原本已超过 600 行的存量旧文件时，**仅允许做最小必要改动**。
   - 严禁未经用户明确指令对存量超长文件进行全量重写或顺手大规模重构。
   - 修改完成后在汇报中提示该文件已超 600 行并建议后续拆分；**同一会话内同一文件只提示一次**。轻量任务以一句话回报满足此提示，不触发完整汇报。
3. **前端样式约束**：
   - 先检查项目已有样式体系（`package.json`、配置文件、现有组件），**已有体系则沿用**（如 Ant Design、Element、CSS Modules、已有 Tailwind 配置等）。
   - 无既有体系且为新建独立页面时，默认使用 **Tailwind CSS**。
   - 若用户要求“可直接双击离线打开的单文件 HTML 页面”或按 `zhuoh-ppt-maker` 文献汇报模式产出文献汇报网页，允许使用内联 `<style>`，并在汇报中注明。
## 二、交付前自检清单
轻量任务只核对与本次改动直接相关的项；事实与安全底线不豁免。输出代码或结束任务前逐项核对，任一项不达标须先修正再交付。行数必须用一次性命令实测，不得估算（Git Bash：`wc -l <文件>`；PowerShell：`(Get-Content -LiteralPath <文件>).Count`）。
- [ ] **行数核对**：本次新建或整文件重写的源码/组件文件，实测总行数是否均 ≤ 600 行？豁免文件是否已在汇报中说明？
- [ ] **存量保护**：若修改了原本 > 600 行的旧文件，是否严格控制为最小局部改动，且已在汇报中提示拆分（同一会话同一文件仅一次）？
- [ ] **样式合规**：是否已先检查并沿用项目既有样式体系？无既有体系的新建页面是否使用 Tailwind CSS？因离线单页 HTML 使用内联 CSS 的，是否已在汇报中注明？
